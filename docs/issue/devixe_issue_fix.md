# マイク初期化の改善とデバイス選択UIのスマート化タスク分解

このドキュメントでは、友達とのビデオチャット時に発生するマイクの不自然な切り替え（起動時のチラつきや二重ロード）の解消と、デバイス選択UIをスマートかつプレミアムに刷新するためのタスクを分解し、順番に実装・検証を行えるように管理します。

---

## 📋 タスク一覧

### 【タスク1】 `PreJoin.tsx` の初期化フローの改善（二重ロード防止・マイク切り替えの解消）
- [x] **1.1 Cookie取得と優先制約（ideal constraints）の即時適用**
  - `initializeMedia` の開始時にCookieからマイク・カメラの保存情報を読み込み、最初の `getUserMedia` 呼び出し時点で `{ deviceId: { ideal: savedId } }` を制約として設定する。
- [x] **1.2 起動デバイスの判定とストリームの再利用ロジックの実装**
  - `enumerateDevices` 後、実際に起動したトラックのデバイスID（`track.getSettings().deviceId`）を取得する。
  - 最終決定した優先デバイス（保存デバイスまたは既定デバイス）が、現在オープンしているトラックのデバイスIDと一致する場合、ストリームを停止・再取得せずにそのまま再利用する。
  - 不一致の場合のみ、古いストリームをクリーンアップして再取得（フォールバック）する。

### 【タスク2】 `Room.tsx` の初期ビデオデバイスの起動バグ修正
- [x] **2.1 `initialSettings` に基づくカメラ制約の設定**
  - 現在 `Room.tsx` の初期化時に `video: true` とハードコードされている部分を修正。
  - `initialSettings?.videoDeviceId` を判定し、`videoConstraints = { deviceId: { ideal: videoDeviceId } }` を動的に生成する。
- [x] **2.2 `Room` 起動時の指定カメラ適用**
  - `getUserMedia` に上記の `videoConstraints` を渡し、事前選択されたカメラが一発で起動するように修正する。

### 【タスク3】 `PreJoin.tsx` のデバイスドロップダウンUIのスマート化
- [ ] **3.1 物理デバイスリストからの重複・仮想項目のクレンジング**
  - デバイス一覧から `deviceId === 'default'` や `'communications'` を除外し、純粋な物理デバイス名のみを一覧表示する。
- [ ] **3.2 「システム既定（OSの設定）」項目の独立配置**
  - ドロップダウン最上部に「システム既定のマイク（スピーカー）」項目を配置し、`deviceId === 'default'` にマッピングする。
- [ ] **3.3 選択状態のチェックマーク可視化**
  - `lucide-react` の `Check` アイコンをインポートし、現在選択中のデバイスの右側に表示する。
  - スピーカー選択およびカメラ選択についても同様に刷新する。

### 【タスク4】 `Room.tsx` のデバイスドロップダウンUIのスマート化
- [ ] **4.1 `Room.tsx` での「システム既定」と物理デバイスの分離表示**
  - PreJoin同様に、マイクおよびスピーカーのドロップダウンUIを刷新し、最上部に「システム既定」を設置、物理マイク・スピーカーをその下にリスト表示する。
- [ ] **4.2 カメラドロップダウンの整理**
  - カメラ一覧も同様に、選択中のカメラにチェックマークを表示するすっきりしたレイアウトにする。

### 【タスク5】 `index.css` のスタイル刷新によるプレミアムなUI表現
- [ ] **5.1 `.device-menu` と `.device-menu-item` のレイアウト強化**
  - メニューアイテムをフレックス表示（`display: flex`）にし、デバイス名（左）とチェックマーク（右）を綺麗に両端配置する。
  - ホバー時の背景変化をより滑らかにし、モダンなダークテーマに合うトランジションを設定する。
- [ ] **5.2 サブ説明文（`.device-item-sub`）などの補助スタイルの追加**
  - 「OS設定のデフォルトデバイスを使用します」といった説明テキスト用のスタイルを調整し、読みやすさとスマートさを高める。

## 🛠 検証・テスト計画

各タスク完了後に以下の観点で動作確認を行います。

1. **タスク1の検証**:
   - 開発サーバーを起動し、事前準備画面（PreJoin）に入る。
   - コンソールログを確認し、「マイクの二重ロードや停止・再生成」が発生していないこと（マイクが最初から正しいデバイスで1回だけ起動すること）を確認する。
2. **タスク2の検証**:
   - PreJoinで内蔵カメラ以外のカメラ（接続されている場合）を選択し、ルームに参加する。
   - ルーム移行時にカメラがデフォルトにリセットされず、PreJoinでの選択が維持されていることを確認する。
3. **タスク3 & 4の検証**:
   - PreJoinおよびRoomのコントロールバーから、マイク・カメラ・スピーカーのドロップダウンをクリックする。
   - リスト最上部に「システム既定のデバイス」が美しく表示され、物理デバイス名が重複なく整理されていることを確認する。
   - 選択されたデバイスにチェックマークが表示されることを確認する。
4. **タスク5の検証**:
   - ホバーエフェクトやドロップダウン全体の統一感、レスポンシブ時の崩れがないかをUIデザインとして確認する。
